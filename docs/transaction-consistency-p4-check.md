# 交易一致性检查结果

范围：`internal/app` 订单、支付、退款、发货、商品维护与 `internal/web` 操作入口；测试命令为 `go test ./...`，HTTP 冒烟使用本地 `:18080`。

规则覆盖：库存占用/释放、10 分钟关闭、支付通知鉴权和幂等、迟到支付、退款失败重试、正常退款恢复库存、退款/发货竞争、运营商品维护。

## 检查发现与修复

- [中] 仪表盘模板原先直接输出样式定义，可能导致样式文本进入正文。证据：`internal/web/templates.go` 的模板构造。已改为将样式模板包在 `<style>` 中；HTTP 冒烟确认页面包含 `<style>`。
- [中] 固定服务端时钟或同纳秒事件下，仅使用时间戳生成 ID 存在冲突风险。证据：原 `newID` 实现。已加入 `crypto/rand` 熵；20 路并发下单测试通过。

## 已验证

- 20 路并发抢购：仅 5 单成功，库存为 0。
- 重复取消：第二次返回非法状态，库存不重复释放。
- 重复支付：返回幂等结果，不重复推进订单。
- 退款申请和发货竞争：两个操作仅一个成功，结果为退款审核中或已发货。
- 正常退款首次失败、再次成功：订单完成退款并恢复一次库存。
- 迟到支付退款：进入异常并退款，不恢复已释放库存。
- 运营改价：历史订单按创建时价格快照接受支付。

## 未覆盖或需人工确认

- `go test -race ./...` 未执行成功：当前环境 `CGO_ENABLED=0` 且无 gcc。
- 未执行真实 GitHub PR、CI、部署和视频演示。
